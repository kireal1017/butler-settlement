> **상태 (2026-09-22)**: §11 의 **1~6단계 구현 완료.** 7단계(K-apt 단지 자동 매칭)와

>

> - `server/src/services/ocr.js` 의 `recognize(imagePath) → { text, provider, confidence }` (V2-SPEC §4.1에서 등기부용으로 정의한 것)
> - 계약 작성 화면 (임차인 이름 · 연락처 · 보증금 · 월 차임 · 입주일 · 계약 기간(개월))
> - `POST /api/contracts`

## 1. 무엇을 만드는가

계약 작성 화면 맨 위에 **"계약서 사진으로 채우기"** 를 붙입니다.
임대인이 종이 계약서를 찍어 올리면 아래 6개 필드가 미리 채워지고, 각 필드에 **신뢰도 배지**가 붙습니다.

| 채울 필드 | 계약서 출처 | 화면 필드 |
|---|---|---|
| 보증금 | 제1조 | `deposit` |
| 월 차임 | 제1조 차임(월세) | `monthlyRent` |
| 입주일 | 제2조 인도일 | `moveInDate` |
| 계약 기간(개월) | 제2조 종료일에서 역산 | `termMonths` |
| 임대인 · 임차인 이름 | 계약서 첫 문장 | `landlordName` · `tenantName` |
| 동 · 호 · 전용면적 | [임차주택의 표시] | 세대 매칭용 |

### 범위 밖 (명시적으로 하지 않을 것)

- **Rule Lock 항목의 자동 추출.** 도배·바닥재 면제 기간, 연체 지연이자율, 선수관리비 부담 주체는
  법무부 표준계약서에 **해당 칸 자체가 없습니다.** 제4조 ③은 "수선비용 부담을 합의한다"는
  서술형 예시문일 뿐 구조화된 입력란이 아닙니다. OCR로 읽을 대상이 없으므로 Rule Lock은 수동 입력을 유지합니다.
- **특약사항 위험 조항 경고.** 가치는 있지만 이번 범위가 아닙니다. §10 Phase 2로 미룹니다.
- **계약서 원문 저장.** §7 참조.

## 2. 실측 근거 (이 계획의 전제)

법무부 주택임대차표준계약서에 값을 채워 넣고 인쇄본 스캔 / 손글씨 / 사진촬영 3종으로 OCR한 결과입니다.

**① 금액은 한글과 숫자가 병기됩니다 — 이게 가장 중요합니다**

```
보증          사억오천만                   원정(\ 450,000,000            )
계약금    금 사천오백만     원정(\\5,000,000     )은 계약시에 지불하고
잔     사억오백만  원정(\405,000,000  )은 2022 년   월 Ｌ 일에 지불한다
```

계약금 줄을 보십시오. `45,000,000` 의 **앞자리 4가 역슬래시로 먹혀 `5,000,000`** 이 되었습니다.
숫자만 믿으면 4,500만원이 500만원이 됩니다. 그런데 **한글 "사천오백만"은 정확히 살아남았습니다.**
→ **두 값을 각각 파싱해 대조하는 것이 이 기능의 핵심 안전장치입니다.**

**② 날짜는 잘 읽히지만 사진 품질에서 숫자가 흔들립니다**

```
인쇄 스캔:  상태로 _ 2022 년 "9 월 1 일까지 ... 인도일로부터  2026 년   8 월 31 일까지로 한다.
손글씨:     상태로 _ 2022 년 9 월 1 일까지  ... 인도일로부터 _ 2026 년   8 월 31 _ 일까지로 한다.
사진촬영:   오 왼도하고. 임매지 기간은 인도일로부터 _ 2026 년  6 월 31 일까지로 한다.   ← 8월이 6월로
```

`6월 31일` 은 존재하지 않는 날짜입니다. **달력 유효성 검사만으로 이 오류가 잡힙니다.**

**③ 이름과 세대 정보는 안정적입니다**

```
임대인(김성호     )과 임차인(이지은     )은 아래와 같이 임대차 계약을 체결한다
임차할부분    제103동 제2층 제1204호    면적  84.95
```

**④ 표 안의 빈칸은 조용히 사라집니다**

```
차임(월세)  금      원정은 매월  일에 지불한다(입금계좌:               )
```
전세 계약이라 비어 있던 건지, OCR이 못 읽은 건지 **텍스트만으로는 구분되지 않습니다.**
→ 월 차임 미추출은 `0(전세)` 로 단정하지 말고 **사용자 확인 대상**으로 둡니다.

## 4. 파싱 규칙

### 4.1 먼저 섹션을 자릅니다 — 오매칭 방지

표준계약서에는 **금액처럼 보이는 것이 세 군데 더** 있습니다. 자르지 않으면 반드시 틀립니다.

| 함정 | 위치 | 내용 |
|---|---|---|
| 갱신 전 계약 금액 | [계약내용] **앞** | `계약 기간: . . . ~ . . . 보증금: 원, 차임: 월 원` |
| 중개보수 | 제12조 | `거래 가액의 %인 원` |
| 신고의무 안내 | 별지1 (4페이지) | `보증금 6천만원 또는 월차임 30만원을 초과하여` |

```js
// 1) [계약내용] 이후만 본다 → 갱신 전 계약 블록 제거
const body = text.split(/\[\s*계\s*약\s*내\s*용\s*\]/)[1] ?? text;

// 2) 제3조 전까지만 본다 → 제12조·별지1 제거
const head = body.split(/제\s*3\s*조/)[0] ?? body;

// 3) 금액 구역은 "지불하기로 한다" 이후 → 제1조 제목의 '보증금' 글자 제외
const money = head.split(/지불하기로\s*한다/)[1] ?? head;
```

이름·세대 정보는 [계약내용] **앞** 구역에서 찾습니다.

### 4.2 금액 — 한글·숫자 이중 추출

OCR은 글자 사이 공백이 튀므로 **고정 문자열 사이마다 `\s*`** 를 넣습니다 (V2-SPEC §4.2와 동일 원칙).

```js
// '보증금'에서 '금'이 탈락한 실측 사례가 있으므로 금? 로 둔다
const DEPOSIT = /보\s*증\s*금?\s*([^원]{0,40}?)\s*원\s*정\s*\(\s*[\\₩\s]*([0-9,\s]*)\)/;
const RENT    = /차\s*임\s*\(\s*월\s*세\s*\)\s*[|｜]?\s*금?\s*([^원]{0,40}?)\s*원\s*정/;
```

두 캡처를 각각 해석합니다.

- **한글값** `hangul` — `parseKoreanAmount('사억오천만')` → `450000000`
- **숫자값** `arabic` — `'450,000,000'` → `450000000`.
  단, 앞에 붙은 `\`·`₩`·공백을 버릴 때 **숫자 한 자리가 함께 사라질 수 있음**을 전제합니다.

차임은 괄호 병기가 없는 서식이라 한글값만 나옵니다. 그래서 `RENT` 는 한글 하나만 캡처합니다.

### 4.3 `koreanAmount.js`

```js
const DIGIT = { 일:1, 이:2, 삼:3, 사:4, 오:5, 육:6, 칠:7, 팔:8, 구:9 };
const SMALL = { 십:10, 백:100, 천:1000 };
const BIG   = { 만:1e4, 억:1e8, 조:1e12 };

/** '사억오천만' → 450000000. 해석 불가 글자가 섞이면 null. */
export function parseKoreanAmount(raw) {
  // '원정'·'원'을 먼저 떼지 않으면 한글이라 살아남아 파싱이 깨진다 (검증 완료)
  const s = String(raw ?? '')
    .replace(/원\s*정|원|정/g, '')
    .replace(/[^가-힣]/g, '');
  if (!s) return null;
  let total = 0, section = 0, cur = 0;
  for (const ch of s) {
    if (DIGIT[ch] != null)      cur = DIGIT[ch];
    else if (SMALL[ch] != null) { section += (cur || 1) * SMALL[ch]; cur = 0; }
    else if (BIG[ch] != null)   { total += (section + cur) * BIG[ch]; section = 0; cur = 0; }
    else return null;                       // OCR 잡음 → 실패로 처리
  }
  return total + section + cur;
}
```

반드시 테스트할 케이스 — **실측 계약서에서 나온 값들입니다.**

| 입력 | 기대 |
|---|---|
| `사억오천만` | 450000000 |
| `사천오백만` | 45000000 |
| `사억오백만` | 405000000 |
| `일억` | 100000000 |
| `삼십만` | 300000 |
| `오천만원정` | 50000000 (비한글 제거 후) |
| `사억오처만` | null (`처`는 미지 글자) |

> 위 7건은 실제로 돌려서 전부 통과를 확인했습니다. 그대로 테스트로 옮기세요.

### 4.4 날짜 — 제2조

```js
// 실측: '상태로 _ 2022 년 "9 월 1 일까지'  ← 밑줄·따옴표 잡음이 낀다
const HANDOVER = /상\s*태\s*로[\s_"'~]*(\d{4})\s*년[\s_"'~]*(\d{1,2})\s*월[\s_"'~]*(\d{1,2})\s*일\s*까\s*지/;
// 실측: '인도일로부터 _ 2026 년   8 월 31 _ 일까지로 한다.'
const EXPIRY   = /인\s*도\s*일\s*로\s*부\s*터[\s_"'~]*(\d{4})\s*년[\s_"'~]*(\d{1,2})\s*월[\s_"'~]*(\d{1,2})\s*[\s_]*일\s*까\s*지/;
```

**두 단계 검증을 반드시 통과시킵니다.**

1. **달력 유효성** — `new Date(y, m-1, d)` 가 입력과 같은 날짜로 되돌아오는지.
   `2026-06-31` 은 여기서 걸립니다 (사진촬영 실측 오류).
2. **기간 상식** — `expiry > handover` 이고 간격이 `6 ~ 120개월` 이내인지.

**계약 기간(개월) 역산** — 화면이 `termMonths` 를 받으므로:

```js
let months = (ey - hy) * 12 + (em - hm);
if (ed < hd - 1) months -= 1;          // 표준계약서는 '만료일 = 시작일 하루 전'이 관행
// 12·24·36 같은 정수 개월에서 ±3일 이내면 스냅, 아니면 신뢰도 강등
```

### 4.5 이름 · 세대

```js
const PARTIES = /임\s*대\s*인\s*\(\s*([가-힣]{2,5})[^)]*\)\s*과?\s*임\s*차\s*인\s*\(\s*([가-힣]{2,5})/;
const UNIT    = /제\s*([0-9]{1,4})\s*동\s*제\s*[0-9]+\s*층\s*제\s*([0-9]{1,5})\s*호/;
const AREA    = /([0-9]{1,3}\.[0-9]{1,2})/;   // ※ [임차주택의 표시] 구역으로 자른 뒤에만 쓸 것
```

> `AREA` 는 토지 면적(`12,458.3`)과 건물 면적(`84.95`)이 같은 구역에 있습니다.
> **`임차할부분` 행으로 한 번 더 자른 뒤** 찾으세요. 등기부 전용면적과 같은 함정입니다 (V2-SPEC §4.2 ③).

## 5. 신뢰도 모델

필드마다 `high | medium | low` 를 매기고 **화면에서 눈에 보이게** 합니다.

| 필드 | high | medium | low |
|---|---|---|---|
| 보증금 | 한글값 == 숫자값 | 한쪽만 추출됨 | 둘 다 실패 **또는 불일치** |
| 월 차임 | 한글값 파싱 성공 | — | 미추출 (전세로 단정 금지) |
| 입주일 | 달력·기간 검증 통과 | 통과했으나 사진 품질 낮음 | 검증 실패 |
| 계약 기간 | 정수 개월 스냅 성공 | 스냅 실패(단수 개월) | 날짜 둘 중 하나 실패 |
| 이름 | 2~5자 한글 매칭 | — | 미추출 |

**두 값이 불일치하면 `low` 로 보내고 칸을 비웁니다.** 이때 "45,000,000 / 5,000,000 중 확인 필요"처럼
**두 후보를 함께 보여줍니다.** 조용히 하나를 고르는 것이 가장 위험합니다.

화면 처리:

- `high` → 값 채움 + 회색 "자동 입력" 배지
- `medium` → 값 채움 + 노란 "확인 필요" 배지, 입력칸 테두리 강조
- `low` → **빈칸 유지** + 빨간 "읽지 못함" 안내

> **`high` 라도 저장 전 사용자 확인을 거칩니다.** 이 기능은 타이핑을 줄이는 것이지
> 계약 조건을 확정하는 것이 아닙니다. Rule Lock 확정 버튼까지 가려면 사용자가 한 번은 눈으로 봅니다.

## 6. API

```
POST /api/contracts/ocr
  multipart/form-data: file (image/jpeg | image/png | application/pdf, ≤10MB)

200 {
  provider: 'clova' | 'fixture' | ...,
  fields: {
    deposit:      { value: 450000000, confidence: 'high',   source: { hangul: '사억오천만', arabic: '450,000,000' } },
    monthlyRent:  { value: null,      confidence: 'low',    source: {} },
    moveInDate:   { value: '2022-09-01', confidence: 'high', source: { raw: '2022 년 9 월 1 일' } },
    termMonths:   { value: 48,        confidence: 'high',   source: { expiry: '2026-08-31' } },
    landlordName: { value: '김성호',   confidence: 'high' },
    tenantName:   { value: '이지은',   confidence: 'high' },
    dong:         { value: '103',     confidence: 'high' },
    ho:           { value: '1204',    confidence: 'high' },
    exclusiveArea:{ value: 84.95,     confidence: 'medium' }
  },
  warnings: [ '월 차임을 읽지 못했습니다. 전세 계약이면 0으로 두고, 아니면 직접 입력하세요.' ]
}

422 { error: 'parse_failed', message: '계약서 양식을 인식하지 못했습니다. 직접 입력해 주세요.' }
```

**설계 원칙**

- 이 엔드포인트는 **아무것도 저장하지 않습니다.** 파싱 결과만 돌려주고 끝냅니다.
  계약 생성은 기존 `POST /api/contracts` 가 그대로 담당합니다.
- 라우터에는 검증만 두고 파싱은 `services/contract.js` 에 둡니다 (CLAUDE.md 계층 규칙).
- `parse_failed` 여도 **화면은 계속 진행 가능해야 합니다.** 수동 입력이 항상 기본값입니다.

## 7. 개인정보

계약서 3페이지에는 **임대인·임차인의 주민등록번호와 연락처**가 있습니다.
등기부(V2-SPEC §5)보다 민감도가 높습니다.

- **1~2페이지만 처리합니다.** PDF면 앞 2페이지만, 이미지면 업로드 자체를 1장으로 제한하고
  화면에 "계약서 **1페이지**(보증금·기간이 있는 면)를 올려주세요"라고 안내합니다.
- **OCR 원문(`text`)을 DB에 저장하지 않습니다.** 응답 후 메모리에서 버립니다.
  등기부는 소유권 검증 근거로 남겨야 하지만, 계약서 원본은 임대인이 이미 갖고 있습니다.
- **업로드 파일은 파싱 직후 삭제합니다.** `server/uploads/**` 에 남기지 않습니다.
- 그럼에도 응답을 만들 때 주민번호 패턴 `/\d{6}\s*-\s*\d{7}/` 은 마스킹합니다 (2중 방어).

## 8. CLOVA OCR 실연동

`services/ocr.js` 의 `recognize()` 시그니처만 지키면 됩니다. 계약서 파서는 공급자를 모릅니다.

```
OCR_PROVIDER=clova
OCR_API_KEY=<X-OCR-SECRET>
OCR_INVOKE_URL=https://<도메인>.apigw.ntruss.com/custom/v1/<id>/<key>/general
```

```js
// POST, 헤더: X-OCR-SECRET: <secret>, Content-Type: application/json
{
  version: 'V2',
  requestId: crypto.randomUUID(),
  timestamp: Date.now(),
  images: [{ format: 'jpg', name: 'contract', data: <base64> }]
}
// 응답: images[0].fields[] = { inferText, inferConfidence, boundingPoly }
```

**주의 세 가지**

1. **General OCR은 필드를 좌표 순으로 흩뿌려 줍니다.** `fields[]` 를 그대로 이으면 표가 뒤섞입니다.
   `boundingPoly.vertices` 의 y값으로 줄을 묶고(같은 줄 판정: y 중심 차이 < 글자 높이의 0.6배),
   각 줄 안에서 x 오름차순 정렬해 **줄 단위 텍스트로 재조립**한 뒤 파서에 넘기세요.
   §4의 정규식은 전부 "한 줄" 기준입니다.
2. **`inferConfidence` 를 필드 신뢰도에 섞지 마세요.** 그것은 글자 인식 확신도일 뿐,
   `\5,000,000` 같은 오류에서도 높게 나옵니다. §5의 교차검증이 실질적 방어선입니다.
   단, 금액·날짜를 구성한 토큰의 `inferConfidence` 최솟값이 0.8 미만이면 `high` → `medium` 으로 강등하세요.
3. **Template OCR이 정확도는 더 높습니다.** 표준계약서 양식을 콘솔에 등록하면 필드 단위로 바로 받습니다.
   다만 서식이 조금만 달라도 실패하므로, **Template 우선 → 실패 시 General 폴백** 순서를 권합니다.
   PoC 단계에서는 General만으로 충분합니다.

**전처리** (사진 촬영본 정확도가 눈에 띄게 낮았습니다)

업로드 시 클라이언트에서 장변 2000px 이상으로 리사이즈하고, 서버에서 그레이스케일 + 기울기 보정을 겁니다.
화면에는 "**스캔본이 가장 정확합니다. 사진이면 정면에서, 그림자 없이**" 를 안내로 둡니다.

## 9. K-apt 연계

OCR로 얻은 동·호·면적으로 세대를 자동 매칭합니다.

1. 소재지 텍스트에서 단지명을 뽑아 `kapt.searchComplexes(단지명)` 호출
   (키 없으면 `null` → 기존대로 로컬 DB 검색으로 폴백)
2. 후보가 1건이면 선택, 2건 이상이면 **사용자에게 고르게 합니다.** 자동 선택 금지.
3. 매칭된 `kaptCode` + 동·호로 기존 `units` 조회 → 있으면 연결, 없으면 새 세대 생성 폼을 미리 채움
4. **전용면적은 OCR 값보다 K-apt·등기부 값을 우선합니다.**
   장기수선충당금 계산의 곱셈 인자라 틀리면 금액이 통째로 어긋납니다.

## 부록 · Phase 2 — 특약사항 위험 스캔

이번 범위는 아니지만, 같은 OCR 결과를 재활용해 만들 수 있습니다.
[특약사항] 구역을 잘라 아래 키워드를 찾고 **경고만** 띄우는 기능입니다. 값을 자동으로 바꾸지는 않습니다.

| 키워드 | 경고 |
|---|---|
| `장기수선충당금` + `임차인` | 소유자 부담 원칙(공동주택관리법 시행령 제31조 제8항)과 충돌 |
| `원상복구` + `전부` / `일체` | 통상손모까지 임차인에게 지우는 조항일 수 있음 |
| `저당권` · `담보권` | 보증금 보호 특약 — 있으면 정상, 없으면 안내 |
| `국세` · `지방세` | 선순위 조세채권 관련 특약 유무 |

실측에서 특약사항 구역은 OCR 손상이 가장 심했습니다
(`10만원 이하의 소모성 수선비는 일차인이` — `임차인`이 `일차인`으로).
따라서 **정확한 조항 해석이 아니라 "여기 확인해 보세요" 수준의 플래그**로만 설계하세요.
